# McKinsey | 은행 고객응대 Agent의 Frugal AI 비용 워터폴 — Exhibit 1

- 회사/제목: McKinsey, *Closing banking’s AI value gap: A CEO guide*.
- 게시일: **2026-10-30**. 수정일: 미공개. 열람일: **2026-11-01**.
- URL: https://www.mckinsey.com/industries/financial-services/our-insights/closing-bankings-ai-value-gap-a-ceo-guide
- 그림: Exhibit 1, *Frugal AI* 비용 구성 워터폴. 공식 SVGZ URL은 `record.json > original_image_url` 참조. 도구에서 SVGZ 원본 열람 실패(지원하지 않는 콘텐츠 형식). 원본 파일은 저장하지 않았다.
- 출처: **McKinsey Frugal AI Framework**. 월 약 100,000건의 상담을 가정한 **설명용 모델**로, 특정 은행의 실측 성과가 아니다. 표본·조사시점·비용의 실제 USD·구간별 분산·모형 상세는 미공개.

## 2. 원문 요지
은행이 AI 사용 범위를 넓히더라도 기업의 재무 성과로 연결하지 못하는 문제가 있다. 모델·문맥·인프라·사람의 개입 설계가 단위 업무당 처리비용에 큰 차이를 낳을 수 있다. 은행의 AI 운영체계는 재사용 가능성과 비용 측정을 함께 고려해야 한다.

## 3. 핵심 메시지 — Agent 해석
**따라서 은행 경영자는 AI Agent의 단위 업무비용을 초기부터 측정하고, 과도한 추론·문맥 재전송·고비용 모델 선택을 줄이는 설계를 우선 검토해야 한다.** 아래 감소율은 설명용 사례이며 실적·절감 보장이 아니다.

## 4. 비즈니스 맥락 → 숫자 → 판단
| 단계 | 원문 설명·선택 | 처음 설계 대비 비용 변화 | 기준·단위 | 관리 의사결정(제안) |
|---|---|---:|---|---|
| Typical design | 고성능 모델 우선, 캐시·모델 분기 없음 | **100** | 기준 100 | 기준 비용 정의·측정 |
| Prompt engineering | 반복 호출 제한, 필요한 추론 수준 조절 | **-10%p** | 최초 기준 대비 | 호출 수와 토큰 사용량 관측 |
| Context handling | 목적별 작업문맥, 캐시 접두부 | **-20%p** | 최초 기준 대비 | 전체 대화기록 반복전송 제한 |
| Right-sized model | 업무 난도별 0~2단계 모델 티어 | **-40%p** | 최초 기준 대비 | 쉬운 작업에 비싼 모델 남용 방지 |
| Infrastructure/operations | 재시도 제한과 배치 처리 | **-10%p** | 최초 기준 대비 | 불필요한 실행·Retry 제어 |
| Human escalation | 효과를 고려한 선택적 검수 | **-4%p** | 최초 기준 대비 | 사람 검수 조건 최적화 |
| Frugal design | 설명용 최종 비용 | **16** | 최초 100 기준 | 비용·품질의 실제 A/B 검증 |

`100 - 10 - 20 - 40 - 10 - 4 = 16`이며 감소 항목은 **동일한 최초 기준 100의 %p**다. 각 단계를 연속해서 10%, 20% 할인하는 복리 계산이 아니다.

## 5. 원문 시각 구조 관찰 범위
- `insight_type`: 구성(비용 감소 기여도). 공식 HTML 이미지 설명에서 차트 유형이 `waterfall`임을 확인했으나, **SVGZ 원본 픽셀을 직접 열지 못해 축·색·배치의 원본 관찰은 불가**.
- 생성 차트: 첫 막대는 100, 각 중간 단계는 현재 남은 비용의 윗부분부터 감소치를 떼어낸 부유형 막대, 마지막 막대는 16.
- `x`: 조정 항목의 순서. `y`: 최초 비용 대비 비율(0~100%), 범례는 불필요하도록 직접 라벨. `color`: 기본 총액·감소·잔존의 세 구간. `size`: 별도 없음. `panel`: 1개.
- 축: 0부터 시작, 이중축·로그축·축 절단 없음. 제목은 '조건부 시나리오에서 16%까지 감소할 수 있다'는 메시지를 서술하는 액션 타이틀로 재작성.
- 가독성: 단계별 기여가 직관적이지만, 실제 검증하지 않은 비용효과의 단순 가산을 일반화하면 안 된다.

## 6. 데이터 확보와 품질
`data.csv`의 100, -10, -20, -40, -10, -4, 16은 공식 **Exhibit 1 HTML 대체텍스트에 나오는 값**을 `reported`로 보존했다. 다만 여기서 reported는 원문의 설명용 모델이 제시한 숫자라는 뜻이지 실측된 비용을 뜻하지 않는다.

기간: 2026년 기사에 실린 설명용 설계. 단위는 최초 비용=100에 대한 %, 달러금액/현실 운영단가 미공개. 인허가·품질·재작업·지연비용 포함 여부도 미공개. 단계 순서와 음수 및 비용 합계, 기준 분모가 일관적인지 검증했다.

## 7. 재사용 `data_recipe` (제안, 원본의 실제 내부 모델링 방식 아님)
1. 관측 단위 `case_id × agent_configuration`으로 `tokens_input`, `tokens_output`, `model_name`, `calls`, `retry_count`, `cache_hit`, `human_review_minutes`, `unit_price`, `resolved_flag`, `rework_cost`를 수집한다.
2. LLM API 로그, 관제 DB, 인건비/클라우드 비용표, CS 운영 기록에서 비용을 수집한다.
3. 중복 재시도·중간 실패·해결되지 않은 상담을 분리하고 누락된 비용은 임의로 0 처리하지 않는다.
4. 동일한 고객문의 복잡도·해결 정의·품질·추정 기간의 비교를 확인한다.
5. `unit_cost = (model_cost + infra_cost + human_cost + rework_cost) / resolved_cases`로 공통 분모 기준 계산.
6. 통제된 A/B 또는 순차실험에서 비용 항목 변화와 상호작용을 확인한 뒤, **중복되지 않는** 기여도만 워터폴에 넣는다.
7. 총효과에 불확실성 구간·오류율·고객 만족도를 연결하고 해당 데이터 패턴에 맞춰 제목을 바꾼다.

## 8. 메시지 성립 조건·반례·한계
동일 품질과 상담 건수에서 단위 비용이 실측으로 감소할 때만 비용절감 메시지가 성립한다. 모델 티어 축소 때문에 재작업·정확도 악화가 발생하거나 비용 항목들이 서로 겹치면 실제 절감은 더 작거나 반대일 수 있다. 이 그래프만으로 실제 은행 전체 투자수익률이나 모든 고객 업무의 절감률을 추정할 수 없다.

## 9. 재사용·검증
- `data.csv`의 `category`, `value`, `sort_order`, `provenance`; `config.json`의 `THEME.source/neutral`에서 팔레트·폰트·그리드·크기·여백; `CONTEXT`에서 제목·축·주석을 수정한다.
- 실행: `python chart.py --theme source --data data.csv --config config.json --output output.png` 또는 `--theme neutral --output output_neutral.png`.
- 적합한 사례: 무역 계약 Agent의 계약검토 1건당 LLM·재시도·검수비용 절감 구조.
- 실행 환경: Python 3.13.5, matplotlib 3.10.8, pandas 2.2.3.
- **원본 대비 충실도 점수 null, `unverified`**: 공식 SVGZ 시각 확인 불가. Python 실행·원문 설명 수치 검증과 원본 시각 충실도는 구분된다. 학습·배포권한 미확인, 사용자 검수 대기.
